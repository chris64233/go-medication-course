# go-medication-course

本项目用于 GSB 评测，基础仓库只保留可运行的 Go 模块骨架。

## 概述

内存实现的服药疗程领域模型（线程安全），支持：

- 疗程创建、暂停/恢复、完成/取消；
- 计划服药时间点的展开与查询；
- 服药登记（含补记）；
- **处方调整的版本化记录**：调整只影响尚未发生的计划点，历史事实不可变。

核心类型见 `course.go`，服务入口见 `service.go`，内部展开/快照/幂等逻辑见 `internal.go`。

## 核心规则

### 1. 版本化处方调整

- `Service.Adjust` 提交一个新的 `PrescriptionVersion`，记录调整人、原因、提交时间、生效时间。
- 版本号从 1 开始严格递增；生效时间必须晚于上一版本、不早于提交时刻、
  且不能早于任何已确认服药事实的计划时间（否则返回 `ErrEffectiveBeforeIntake`）。
- 已完成或已取消的疗程不能创建调整（`ErrCourseClosed`）；暂停中也不允许调整（`ErrCoursePaused`）。

### 2. 计划展开与历史不可变

- 每个计划点 `PlannedPoint` 在展开时冻结 `Version` 与 `Dosage` 快照。
- 查询 `Schedule(from, to)` 按计划时间选择当时生效的版本（`EffectiveAt <= t` 的最后一个版本），
  返回的每行明确标注该时间点采用的版本号。
- 调整时：生效时间之后、尚未登记的计划点被删除并按新版本的剂量/频次重排；
  生效时间之前的历史点、以及所有已登记服药事实（`IntakeRecord`）原样保留，
  不会被重算或覆盖。
- 已登记记录始终保留原版本号与原剂量。

### 3. 补记限制

- 补记（登记时刻晚于计划时刻）必须携带该计划点冻结的历史版本；
  试图用新版本号登记历史点会得到 `ErrVersionConflict`。
- 补记事实标记 `Backfilled=true`，不会伪装成新版本下的正常服药。

### 4. 并发裁决

- 服药登记、处方调整、暂停/恢复、完成/取消共用同一把互斥锁，
  以同一处方版本链和疗程状态串行裁决。
- 登记必须携带 `ExpectedVersion`；调整后携带旧版本登记未来计划点返回 `ErrVersionConflict`。
- 重复登记同一计划点返回 `ErrAlreadyRegistered`。
- 完成时刻之后的计划点置为 `voided`（保留可审计，不删除），不可再登记；
  完成时刻之前未服药的点仍允许补记。取消则所有未服药点立即作废。

### 5. 幂等

- 调整请求必须携带外部请求号 `RequestID`：
  - 同号且剂量、频次、生效时间等内容完全一致：返回原调整，不新增版本；
  - 同号但任一内容不同：返回 `ErrRequestConflict`。
- 服药登记同样支持可选 `RequestID` 幂等。
- 所有校验先于任何写入，调整失败时计划与服药记录不会部分改变。

## 查询接口

- `History(courseID)`：按版本号升序返回全部处方版本（含初始版本）。
- `Schedule(courseID, from, to)`：按时间展开计划，每行包含 `ScheduledAt`、
  `Version`、`Dosage`、`Status`，已登记行附带不可变的 `Intake` 快照。
- `Intakes(courseID)`：返回全部已确认服药事实。
- `GetCourse(id)`：返回疗程整体只读快照 `CourseSnapshot`。

## 运行测试

```sh
go test -race ./...
```

测试覆盖：跨版本计划展开、边界生效时间、生效时间约束、版本冲突、
补记限制、暂停/恢复、完成/取消、并发登记、幂等成功/冲突与失败原子性。
